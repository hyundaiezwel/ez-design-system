색

step 번호가 곧 흰 배경 대비비다. 40이 3:1, 50이 4.5:1, 70이 7:1, 90이 15:1. 아래 칩의 대비 수치는 지금 화면에 적용된 면 색 기준으로 즉석 계산한 값이다 — 위 스위치를 다크나 고대비로 바꾸면 숫자가 따라 바뀐다.

● 표시는 약속이 걸린 단계(40 / 50 / 70 / 90)다. 값은 HSL 이분탐색으로 목표 상대휘도를 맞춰 생성했고 WCAG 공식으로 재검증했다 — 한 단계만 임의로 손보면 약속이 깨진다.

역할 토큰

화면 CSS가 참조하는 유일한 층. primitive(--ez-color-*)를 화면에서 직접 쓰면 역할이 사라지고 대비 보장도 깨진다.

토큰값면 대비쓰는 곳

--ez-text-disabled와 --ez-border-default는 대비가 낮다. 전자는 비활성 요소라 WCAG 예외이고 후자는 장식이다 — 경계선만으로 정보를 전달하지 않는다.

타이포

본문 13px. 굵기는 400 / 500 / 700 세 종뿐이다 — 500은 UI 라벨(버튼·탭·표 헤더)에만 쓴다. 줄간격 하한은 150%.

전 단계가 calc(Npx + var(--ez-font-size-offset))이라 상단 「글자」 스위치 하나로 같이 커진다. KRDS 본문 하한 17px은 대국민 서비스 기준이라 따르지 않았다 — 업무 화면의 정보밀도와 상충한다.

접근성

목표는 WCAG 2.1 AA. 대부분은 토큰과 컴포넌트가 처리한다. 사람이 챙길 것만 남겼다.

  • ✓ 마우스를 치우고 Tab만으로 끝까지 조작된다
  • ✓ 포커스가 어디 있는지 항상 보인다 (outline: none을 쓰지 않았다)
  • ✓ 모달에서 Tab이 뒤로 새지 않고, 닫으면 원래 자리로 돌아온다
  • ✓ 아이콘만 있는 버튼에 aria-label이 있다
  • ✓ 오류가 색 외 단서(문구)와 함께 전달된다
  • ✓ 브라우저 200% 확대에서 가로 스크롤이 두 방향으로 나지 않는다
  • ✓ 위 「선명한 화면」 스위치를 켜도 읽힌다
  • ✓ 색각 시뮬레이터로 적록색약을 확인했다

자동 점검은 npx @axe-core/cli <url>. 라벨 누락·대비·ARIA 오용은 잡지만 포커스 순서·색 외 단서·의미 있는 대체 텍스트는 못 잡는다 — 실제 문제의 절반쯤이다.
