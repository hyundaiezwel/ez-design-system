# 기초 — 토큰 체계

정본은 `src/styles/tokens.css`다. 이 문서는 **왜 그렇게 생겼는지**와
**어떻게 쓰는지**만 적는다. 값이 궁금하면 파일을 본다.

---

## 1. 두 층, 한 방향

```
primitive   --ez-color-gray-50        값 그 자체
    ↓  참조
semantic    --ez-text-muted           역할 이름
    ↓  참조
화면 CSS    color: var(--ez-text-muted)
```

**화면은 semantic만 쓴다.** primitive를 화면에서 참조하는 순간 "이 회색이 어떤 역할이었는지"가
사라지고, 나중에 값을 바꿀 때 무엇이 도는지 알 수 없게 된다. h-pms가 정확히 그 상태다
([비교 분석](/comparison) §2).

리뷰에서 걸러야 할 것은 딱 두 가지다.

- 화면 CSS에 `--ez-color-*`가 보이면 → semantic 토큰이 없다는 뜻. 토큰을 추가하고 그걸 쓴다.
- 화면 CSS에 hex·px 리터럴이 보이면 → 토큰화 대상.

## 2. step 번호는 대비비 약속이다

색 스케일의 번호는 순서가 아니라 **캔버스(`--ez-surface-canvas`) 대비비**다.

| step | 캔버스 대비 | 쓸 수 있는 곳 |
|---|---|---|
| 5 / 10 | 1.1 / 1.0 | 면 배경 |
| 20 / 30 | 1.2 / 1.7 | 경계선(장식), 비활성 면 |
| **40** | **3:1** | 큰 글씨(19px+ 또는 15px bold), 아이콘, UI 경계선 |
| **50** | **4.5:1** | **본문 글씨 하한** |
| 60 | 5.8 | 본문 강조 |
| **70** | **7:1** | AAA · 선명한 화면 모드 본문 |
| 80 | 10 | 제목 · 다크 raised 면 |
| **90** | **15:1** | 최대 강조 · 다크 기본 면 |
| 95 | 17 | 다크 캔버스 |

### 기준면이 흰색이 아닌 이유 (v1.1.0에서 바뀜)

v1.0.0은 흰 배경을 기준으로 잡았다. 그런데 글자가 실제로 놓이는 **가장 어두운 면은 캔버스**다.
그래서 카드 안(흰 면)에서는 통과하고 페이지 배경 위에서만 미달하는 구멍이 났다 —
`--ez-text-muted`가 흰 면 4.48:1, 캔버스 위 3.90:1이었다. 눈으로는 안 잡히는 종류다.

기준면을 가장 어두운 면으로 내리면 더 밝은 면에서는 자동으로 통과한다. 그리고 이 기준
하나가 **두 용도를 함께** 만족시킨다.

1. 밝은 면 위의 어두운 글자 — 캔버스에서 통과하면 흰 면에서도 통과
2. 색 면 위의 흰 글자 — 캔버스 기준 4.5:1인 색은 흰 글자 기준 5.3:1이다

값은 `scripts/palette.mjs`가 생성하고(양자화 손실 대비 2% 여유), `scripts/check-contrast.mjs`가
의미 토큰 조합 **278쌍을 라이트·다크·고대비 전 조합에서** 재검증한다. `npm run verify`에 물려 있다.
**눈으로 고친 값이 아니다 — 한 단계만 손보면 약속이 깨진다.**

다크 테마는 같은 약속을 뒤집는다. 가장 밝은 면이 `raised`(gray-80)라 그쪽을 기준으로 잡는다 —
step 30이 5.8:1, step 20이 8.8:1이다. 그래서 라이트가 80/50을 쓰는 자리에 다크는 20/30을 쓴다.

### 이게 주는 것

1. **"이 색 써도 되나"가 사라진다.** 본문이면 50 이상, 아이콘이면 40 이상.
2. **선명한 화면 모드가 공짜다.** 팔레트를 새로 만들지 않고 step만 올린다
   (`--ez-text-muted`: 50 → 70).
3. **다크 테마가 대칭이다.** 값을 새로 고르지 않고 step만 뒤집는다.

## 3. 색 계열

| 계열 | 용도 | 앵커 |
|---|---|---|
| `gray` | 면·글자·경계. hue 215를 섞은 blue-gray | — |
| `primary` | 브랜드·주요 액션 | hue 171.7° (사내 admin 표준 주색의 색상) |
| `secondary` | 보조 액션·링크·정보 | — |
| `success` / `warning` / `danger` | 상태 | — |

브랜드색을 바꿔야 하면 `primary` 11단계를 다시 생성한다. 한 단계만 바꾸지 않는다.
생성 방법은 [`scripts/`](#5-스케일-재생성) 참조.

### 밀도 — 화면 성격이 다르면 여백도 달라야 한다

기본은 **compact**다(목록·폼). 대시보드·통계처럼 위젯 몇 개가 전부인 화면은
`data-density="comfortable"`을 걸어 여백을 키운다.

| 토큰 | compact | comfortable |
|---|---|---|
| `--ez-card-padding` | 16px | **24px** |
| `--ez-card-gap` | 16px | **24px** |
| `--ez-card-radius` | 12px | **16px** |
| `--ez-card-border-width` | 1px | **0** |
| `--ez-card-shadow` | 없음 | `--ez-shadow-raised` |
| `--ez-section-gap` | 16px | 24px |

```html
<main data-density="comfortable"> … </main>
```

여유 밀도에서 **카드 테두리를 버리는 것**이 요점이다. 여백이 충분하면 선이 필요 없고,
선과 여백을 같이 쓰면 시끄럽다. 분리는 여백 + 약한 그림자가 맡는다.

**목록·폼에는 걸지 않는다.** 행 높이가 커지면 30만 행 그리드에서 한 화면에 여덟 줄이 들어간다.

### 숫자를 세우는 단계

`--ez-font-size-3xl`(28px) · `--ez-font-size-4xl`(34px). KPI 값·금액 전용이고 문장에는
쓰지 않는다. 라벨을 `2xs`로 낮추고 값을 `3xl`로 올리면 위계가 크기 대비만으로 선다.

### 차트는 다른 팔레트를 쓴다

`--ez-chart-1` … `--ez-chart-6`. **의미색을 범주에 쓰지 않는다** — success 초록·danger 빨강을
채널 구성 같은 범주에 쓰면 "좋음/나쁨"으로 읽힌다.

| 토큰 | 값 | 캔버스 | 다크 면 |
|---|---|---|---|
| `--ez-chart-1` 틸 | `#38887d` | 3.66 | 4.19 |
| `--ez-chart-2` 네이비 | `#406795` | 5.08 | 3.02 |
| `--ez-chart-3` 오커 | `#a07b3d` | 3.38 | 4.53 |
| `--ez-chart-4` 플럼 | `#7e56ac` | 4.78 | 3.20 |
| `--ez-chart-5` 세이지 | `#468d4f` | 3.52 | 4.35 |
| `--ez-chart-6` 브릭 | `#a15449` | 4.70 | 3.26 |

설계가 셋이다.

1. **채도를 낮춘다.** 완전 채도 6색이 나란히 있으면 어느 계열도 눈에 들어오지 않는다.
2. **휘도를 두 밴드로 번갈아 둔다.** 인접 색상이 비슷해 보여도 밝기로 갈린다.
3. **양쪽 테마에서 3:1 이상**(WCAG 1.4.11 비텍스트 대비)이라 테마별 두 벌이 필요 없다.

패턴(ECharts `aria.decal`)과 함께 쓰는 것을 전제한다 — 색만으로 계열을 가르지 않는다.

**7개 이상이 필요하면 계열을 늘리지 말고 묶어서 '기타'로 접는다.** 사람이 범례에서 구분할 수
있는 색은 그 정도가 한계다.

#### 기본은 두 색이다

계열이 둘이면 `--ez-chart-1` + `--ez-chart-muted`(gray-40)를 쓴다 — 이번 기간 vs 지난 기간,
목표 vs 실적처럼 **비교 쌍**이 업무 차트의 대부분이다. 여섯 색을 다 꺼내는 것은 계열이
셋 이상일 때다.

색을 적게 쓸수록 화면이 조용해진다. 알록달록한 차트는 계열이 많아서가 아니라
**필요 없는데 색을 다 꺼내서** 생긴다.

### 액션 색에 걸린 제약

`--ez-action-primary`는 **step 50**을 가리킨다. 흰 글자를 올려 5.3:1이 나온다.

사내 표준 주색 `#009782`는 **스케일에서 뺐다**(v1.1.0). 캔버스 기준 2.6:1이라 step 40의
약속(3:1)을 만족하지 못하기 때문이다. `--ez-brand`로 따로 두고 **로고·큰 면적 장식에만** 쓴다 —
글자·아이콘·경계선에는 쓰지 않는다. 계승되는 것은 색상(hue)이고, 나란히 놓으면 같은 초록으로 읽힌다.

다크 테마에서는 반대다. 어두운 면에 어두운 버튼을 올릴 수 없으므로 `--ez-action-primary`가
step 30(밝은 쪽)을 가리키고 글자를 어둡게 뒤집는다(`--ez-action-primary-on: gray-95`).

## 4. 색 아닌 토큰

### 간격 — 4px 배수만

`--ez-space-1`(4px) … `--ez-space-12`(48px). 홀수 값이 필요하면 그 레이아웃이 틀린 것이다.

### 크기 — 3종 고정

`--ez-size-sm`(28) / `md`(34) / `lg`(40). 입력·버튼·페이저 버튼이 전부 이 셋 안에서 논다.
줄에 놓인 컨트롤 높이가 서로 다르면 눈이 먼저 알아챈다.

### radius — 3단계

`sm`(4) 뱃지·체크박스 · `md`(8) 입력·버튼 · `lg`(12) 카드·패널·모달.
h-pms는 6/8/10/14/18px 다섯 단계였고 어느 것이 카드인지 규칙이 없었다.

### 글자 — 6단계 + offset

| 토큰 | 기본 | 쓰는 곳 |
|---|---|---|
| `2xs` | 11px | 뱃지, 메타, 힌트 |
| `xs` | 12px | 표, 조회 조건, 보조 |
| `sm` | 13px | **본문** |
| `md` | 14px | 섹션 제목, 모달 타이틀 |
| `lg` | 16px | 카드 제목 |
| `xl` / `2xl` | 20 / 24px | 페이지 타이틀, KPI |

전 단계가 `calc(Npx + var(--ez-font-size-offset))`이라 `data-font-scale`만 바꾸면 따라온다.

굵기는 **400 / 500 / 700 세 종뿐**이다. 500은 UI 라벨(버튼·탭·표 헤더)에만 쓴다.
본문 강조는 700이다. 600·800을 쓰지 않는 이유는 h-pms에서 같은 13px에 500/600/700이 섞여
강조 위계가 읽히지 않았기 때문이다.

줄간격 하한은 150%(`--ez-line-height-normal`)다. `tight`(1.3)는 뱃지·표 셀처럼 한 줄로 끝나는
요소에만 쓴다.

### z-index — 다섯 층

`sticky`(100) < `dropdown`(200) < `panel`(300) < `modal`(400) < `toast`(500).
컴포넌트에서 숫자를 직접 쓰지 않는다. 새 층이 필요하면 여기에 이름을 만든다.

### 모션

`fast`(120ms) 색·테두리 / `normal`(200ms) 패널·모달 / `slow`(320ms) 큰 전환.
`prefers-reduced-motion`에서 전부 0.01ms로 덮이므로 **컴포넌트마다 미디어쿼리를 쓰지 않는다.**
회전 스피너처럼 "멈추면 안 되는" 모션은 컴포넌트가 개별로 대체 표현을 둔다(`EzButton` 참고).

## 5. 스케일 재생성

브랜드색이 바뀌거나 계열을 추가할 때. **한 단계만 고치지 않는다.**

```bash
# scripts/palette.mjs 의 FAMILIES 에서 hue/sat 을 고친 뒤
npm run palette          # tokens.css 의 primitive 값을 다시 씀
npm run check:contrast   # 278쌍 재검증
```

`scripts/palette.mjs`가 목표 상대휘도를 이분탐색으로 맞추고, 밝은 단계는 채도를 낮춰
형광색이 되는 것을 막는다. 대비 목표를 바꾸려면 그 파일의 `CONTRAST_TARGET`을 고친다.

## 6. 테마 스위치

| 속성 | 값 | 효과 |
|---|---|---|
| `data-theme` | `dark` | semantic 재매핑 |
| `data-contrast` | `high` | step 한 단계 진하게 (라이트·다크 양쪽에 겹쳐 적용) |
| `data-font-scale` | `2`~`5` | 단계당 +1px |

셋은 독립이다. `<html data-theme="dark" data-contrast="high" data-font-scale="3">`이 성립한다.

```ts
// 사용자 설정 적용 — 앱 부트스트랩 한 곳에서만 만진다
const root = document.documentElement
root.dataset.theme = prefs.theme            // 'light' | 'dark'
root.dataset.contrast = prefs.highContrast ? 'high' : ''
root.dataset.fontScale = String(prefs.fontScale)  // '1'~'5'
```

`data-theme`을 `light`로 두면 기본값이라 아무 규칙도 안 걸린다 — 지우지 않아도 된다.
